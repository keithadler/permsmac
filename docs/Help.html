Getting started: one permission

macOS keeps the list of what every app is allowed to do in a file that only apps with Full Disk Access may read. So the first time you open Permissions for Mac it asks for that, and nothing else.

  1. Click Open Full Disk Access Settings. System Settings opens at the right pane.
  2. If Permissions for Mac is not in the list, click + (or drag the app in from Applications) and turn its switch on.
  3. Come back. The window fills in on its own within a couple of seconds.
The app opens that file read-only and marked immutable. It has no code that writes to it. The only thing it changes on your Mac is its own history file.

Reading the list

The sidebar lists every kind of permission that at least one app holds, most sensitive first. The dot says how much it matters:

DotMeansExamples
RedCan see or control everything you doScreen Recording, Accessibility, Full Disk Access, Input Monitoring, Camera, Microphone
OrangeReaches a lot of personal data or other appsContacts, Calendars, Photos, Automation, Desktop and Documents folders
GreyNarrow or harmless on its ownReminders, Bluetooth, Focus status

Pick one and the top of the window says, in a sentence, what an app holding it can do. Under it, every app that has it, with how it got it ("you clicked Allow", "set in System Settings", "set by a management profile") and when.

Not installed next to a name means the app is gone but its permission is still on the list. Nothing can use a permission it no longer exists to use, so this is tidy rather than urgent. The Overview's Clean Up… button shows those entries and, when you confirm, clears them one at a time with Apple's own tccutil reset, the same thing the − button in System Settings does. Entries for apps that are still installed, entries stored by path, and Apple's own are never touched. If one of them turns out to be a helper of an app you still use, that app simply asks again.

One detail worth knowing: tccutil refuses a bundle identifier that is not on disk, which for a removed app is always. So for each app, Permissions for Mac creates an empty placeholder bundle carrying that identifier inside its own folder in Application Support, registers it for the length of one tccutil call, then unregisters and deletes it. The placeholder has no code of its own and never leaves that folder.

What changed

Each time it looks (every five minutes while it is open, and whenever you bring it forward), Permissions for Mac keeps a small record of what it saw. The Overview compares the newest record with the one from yesterday, last week, last month or three months ago and lists what was given, refused or removed, and which startup items appeared or went.

When an app gains a red-dot permission while the app is running, you also get a notification. Turn that off in Settings if you prefer to just look.

The first day there is nothing to compare with yet. From the first change on, it shows up here.

Startup

Starts without you lists launch agents (per user and for every user), launch daemons (run as root, at boot) and helper apps bundled inside applications for the older login-item system. Each row says when it runs: at login, on a timer, or only when something asks for it, and whether it restarts itself if it stops. Apple's own are hidden by default; a checkbox shows them.

This part needs no permission: they are plain files anyone can read.

Changing something

Permissions for Mac never changes a permission for an app you have. Apple only allows that in System Settings, and a tool that reads should not also write. What it does is get you there in one click:

  • Change in System Settings… at the top of every permission opens the exact pane.
  • Right-click any row for Show in Finder, the settings pane, or copying the identifier.
  • For a startup item, right-click for Show in Finder. Removing one is a Finder job: move the file to the Trash and log out and in, or use the app's own uninstaller, which is usually cleaner.

Command line

ln -s "/Applications/Permissions for Mac.app/Contents/MacOS/PermsMac" /usr/local/bin/permsmac
permsmac list                     # every allowed permission, grouped
permsmac list --service camera --json
permsmac changes --since 7d       # exit 1 when something changed, so it works in a script
permsmac startup
permsmac orphans                  # grants left behind by removed apps
permsmac orphans --commands       # the tccutil lines, to run yourself
permsmac orphans --clean          # run them now
permsmac explain accessibility
permsmac open "screen recording"  # the System Settings pane
permsmac status

The command reads the same database, so the process running it needs Full Disk Access: the app has it once you grant it; a Terminal command needs Terminal to have it.

Privacy

Nothing leaves the Mac. The only file the app writes is its own history, in ~/Library/Application Support/Permissions for Mac. The daily update check asks GitHub for the latest version number and sends nothing about you; it can be turned off in Settings.

Troubleshooting

The window stays on the Full Disk Access card after I turned the switch on

Quit and reopen the app once. macOS sometimes applies the grant only to new processes.

Location Services and Local Network are missing

macOS keeps those two elsewhere, readable only by root. Their panes are still one click away: permsmac open location.

An app I trust shows up in red

Red is about the power of the permission, not the app. Your screen recorder needs Screen Recording. The list is there so you can see which apps hold that power and decide for yourself.

A permission is listed twice

Some apps hold one grant per version or per install path. Each row is a real entry in the database; System Settings shows only one.
